## 模糊搜索：已确认的代码行为

- ClipboardSearchEngine 只有字面包含、连续全拼和连续首字母匹配。没有分词、多关键词组合、错字容错或多音字消歧。
- normalize 只去除首尾空白并转小写。含空格的关键词不进入拼音路径。
- 因此“微信输入法剪贴板”无法匹配“微信 剪贴板”，“中国北京”无法匹配“zhong guo”；这可以直接从匹配条件确定，但尚不能确认就是用户遇到的具体漏搜。
- README 宣称支持中文分词，与当前实现不符。
- 结果最多取前 50 个；过滤器只搜索宿主 setList 提供的快照，尚未验证它是否包含全部历史。不能将所有漏搜都归因于匹配算法。

下一步：获取一组原文和漏搜关键词，先补回归用例，核对快照中是否有该条目，再决定增加多关键词匹配或调整数据源。匹配与高亮需使用同一规则，并继续检查大历史量搜索耗时。

## 手机搜索结果折叠与深色搜索按钮

第二张截图显示“一天前”的结果卡片堆叠、搜索按钮白底黑图。ADB 暂无设备。
本地留存宿主 APK 的字节码确认：clipboard.v.h 为折叠模式；t() 在 h=1 时返回仅最近内容与首条历史组成的 k，其他模式返回完整列表 b；z(int) 是该模式 setter。过滤后 y() 会重算 k，却不会更改 h。因此搜索刷新后显式通过 z(0) 展开，并在清空搜索或关闭搜索功能时恢复原模式，随后全量重绑。该修复限制于已核对的 v 类与签名，仍需实机确认截图的卡片堆叠是否完全消失。

搜索按钮之前仅在创建时复制图标颜色，已有背景不会随复用更新。已在再次挂载时及布局后重新复制宿主返回按钮的背景，并刷新图标 tint，清除旧 tint/filter。验证连续搜索、跨一天历史、清空、手动展开/折叠、深浅色切换与重开剪贴板。未发布新版本。

## 搜索结果前闪出完整列表

宿主 setList 先装载完整历史，模块原先统一延迟 300ms 再后台过滤，导致完整列表可能先绘制。现有非空关键词时暂存列表 alpha 并设为 0，保持原生布局和导航可见性判断不变；最新结果回放完成后恢复原 alpha。切换关键词时继续隐藏，旧任务受版本号限制不得提前揭示；关闭功能和最新任务失败时恢复。原生列表更新、重复提交相同关键词及清空立即调度，仅连续编辑继续防抖。需实机检查首次搜索、连续搜索、空结果、清空和离页重开，确保未筛选内容不闪现且列表不会残留透明。
